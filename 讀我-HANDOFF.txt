■ 2026-09-01 修好使用者回報的「落子對不到十字交叉線」。
  同一天三個回報其實是同一條 CSS 規則造成的:
    ① 落子時對不到十字交叉線
    ② 落子時會先往右下落子,再回到十字交叉線
    ③ 滑鼠移到白子上,會把白棋子往右下推走

  根因:.intersection 是 <button>,被全域規則
        button:hover:not(:disabled) { transform: translateY(-1px); ... }
        命中。它的優先序 (0,2,1) 高於 .intersection (0,1,0),會整條取代交點的
        transform;舊版交點靠 translate(-50%,-50%) 置中,於是滑鼠一移上去,
        該格連同棋子往右下跳半格,移開才復原。button 還帶
        transition: transform 0.15s ease,所以看起來像「被推走」。

  實測(舊版 15x15,cell 40.12px):
        滑鼠不在上面       → 中心 (1000.38, 531.11),transform: translate(-50%,-50%)
        滑鼠停在剛落的子上 → 中心 (1020.44, 550.15),transform: translateY(-1px)
        位移 +20.06 / +19.04 = 正好半格右下

  修法(commit b99657d + fece9d0):
    1. button:hover 改成 button:not(.intersection):hover
    2. 棋盤上不再有任何百分比位移:
       .stone 改 inset: calc((100% - var(--stone-size)) / 2) 幾何置中,靜止態 transform: none
       .intersection 改負邊距置中(script.js 設 marginLeft / marginTop)
       .star-point / .intersection.last-move::after / .commentary 同樣改 inset 或負邊距
       @keyframes drop / winGlow 移除 translate(-50%,-50%)
    3. .intersection 明寫 transform / filter / transition: none(雙保險)
    4. 順帶修掉一個獨立的真 bug:格線原本用「線的左緣」貼齊座標而非線中心,
       整張網格比棋子右下偏半條線寬(實測 0.78px)
    5. will-change: transform 只在拖曳時開啟

  驗收數字(Playwright,9/13/15/19 四種盤面全點掃描 + 手機直向):
        交點 vs 格線中心最大偏差  1.025px → 0.008px
        棋子 vs 交點              0.008px
        hover 前 / 中 / 移開後位移  0 / 0 / 0
        靜止態 transform          none

■ 怎麼部署(2026-09-01 改成自動)
  CF Pages 專案 5-chess 是 direct upload(不連 Git),所以由
  .github/workflows/deploy-cloudflare.yml 用 wrangler 推上去:

    push 到 main → CI 跑 npm run verify → npm run stage → 部署到 pages.dev

  ⚠ 前提是 repo 已設好兩個 secret(Settings → Secrets and variables → Actions):
      CLOUDFLARE_API_TOKEN   權限 Account → Cloudflare Pages → Edit
      CLOUDFLARE_ACCOUNT_ID  儀表板網址裡那串 32 位十六進位
    **沒設好時部署那一步會被跳過、CI 仍是綠的**(只跑驗證),不會留紅燈,
    但也就沒有自動部署——那段期間要用本機手動出版:

      npm run deploy        # = verify → stage → wrangler pages deploy .deploy

  ★ 哪些檔案會上線,一律以 scripts/stage.mjs 為準,不要另外手抄清單。
    它同時會檢查 service-worker.js 的 CORE_ASSETS 每一項都真的在 .deploy/ 裡
    (少一個 → 安裝時 cache.addAll 整批失敗 → PWA 靜默地不再離線可玩)。

  部署後驗版號:
    curl -s "https://5-chess.pages.dev/service-worker.js?b=<隨機數>" | head -1

■ 版面 / 對位類改動的驗法(這次的教訓)
  · 一定要用真瀏覽器量,而且要量「棋子 vs 格線」——
    不要只量「棋子 vs 它所屬的交點」,兩者會一起位移,量出來永遠是 0,會誤判「重現不出來」。
  · hover 類問題要量三態(hover 前 / 中 / 移開後),並印 getComputedStyle(el).transform。
    transform 前後不一樣 = CSS 被別條規則蓋掉,30 秒就能破,不必先懷疑顯卡。
  · 這條已沉澱進 skill:gpu-safe-rendering 第〇節(hfpc-claude-skills commit 39c15bb)。
